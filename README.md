# Quizeen CBT System Prototype

Quizeen is a client-server Computer-Based Testing (CBT) platform designed for secondary and primary schools. It runs primarily over a school Local Area Network (LAN) connected to a local central server, with built-in offline package (.qzn) support for air-gapped exam rooms. The platform includes live exam monitoring, candidate window focus tracking, automated and manual grading, seeded question and option shuffling, and multi-class performance analytics.

## Repository layout

The project is structured as an npm workspaces monorepo:

```
cbt-system-prototype/
├── apps/
│   ├── manager/          # Teacher and administrator desktop application (Electron + React)
│   ├── student/          # Student examination client (Electron desktop kiosk + Web browser)
│   └── server/           # Central examination hub and API service (Electron GUI + Express)
├── packages/
│   └── shared/           # Core models, validation, UI components, API clients, and .qzn archive utilities
├── installer/            # NSIS multi-user installer scripts and configuration
├── scripts/              # Release packaging, icon generation, and build utilities
├── documentation/        # System documentation and operational guides
└── .qzn-releases/        # Versioned release installers and build manifests
```

## System overview

The suite consists of three interconnected applications:

1. **Central Server (`apps/server`)**:
   - Runs an Express REST API on port 4000 (with automatic fallback to ports 4050, 4100, 4500, or 5000 if port 4000 is occupied or restricted by Windows).
   - Broadcasts network discovery beacons over UDP port 4001 every 2 seconds.
   - Houses an Electron GUI displaying network IP addresses, real-time request logs, interactive latency graphs, auto-start controls, and shutdown warnings.
   - Stores assessments, student records, and submissions in a file-based JSON document store located in `%PROGRAMDATA%\Queez CBT Suite\data` on Windows production installs, preventing permission errors in `Program Files`.

2. **Assessment Manager (`apps/manager`)**:
   - Used by teachers and school administrators to author tests and exams.
   - Configures academic rules including class targets, departments, durations, passing scores, unlock PINs, and shuffling preferences (questions and options).
   - Generates 6-character alphanumeric student access codes individually or in batch.
   - Monitors student test attempts in real time, displays live window blur infractions, and provides manual grading queues for theory or short-answer questions.
   - Exports assessments into encrypted `.qzn` archives and imports existing `.qzn` packages directly into the central server.

3. **Student Examination Station (`apps/student`)**:
   - Runs in desktop kiosk mode (Electron) or via modern web browsers.
   - Authenticates candidates securely using a 6-character Student ID code generated by teachers in the Manager application.
   - Shuffles questions and answer options per candidate using a session-seeded pseudo-random algorithm, preventing students from copying adjacent screens while maintaining 100% accurate answer keys.
   - Monitors window blur and application switches (`infractionCount`), transmitting infractions to the server in real time via `POST /api/submissions/live`.
   - Caches assessment papers locally so students can continue taking tests if the local network disconnects temporarily.
   - Allows supervisors to import `.qzn` packages directly on the station without overriding existing server records.

## Quick start

### Prerequisites
- Node.js version 20 or higher
- npm version 10 or higher
- Windows 10 or 11 (for desktop Electron packaging and NSIS installer compilation)

### Installation
Clone the repository and install all workspace dependencies from the root directory:

```bash
git clone https://github.com/quizeen/cbt-system-prototype.git
cd cbt-system-prototype
npm install
```

### Running development servers

You can start any application individually or run multiple components simultaneously:

```bash
# Student examination client (Web browser interface)
npm run student:dev       # http://localhost:5174

# Student examination client (Electron desktop kiosk)
npm run student:electron

# Manager dashboard (Web browser interface)
npm run manager:dev       # http://localhost:5175

# Manager dashboard (Electron desktop application)
npm run manager:electron

# Central server (Electron desktop GUI)
npm run server:electron   # GUI: http://localhost:5176, API: http://localhost:4000

# Central server (Headless CLI service)
npm run server:dev
```

## Building production releases

The project includes an automated release build script that compiles all three applications and packages them into a single, unified Windows installer:

```bash
# Interactive production release build
npm run release

# Generate Windows application icons (.ico, .png, and .svg)
npm run release:icons

# Version bump only with duplicate release protection
npm run release:bump
```

Compiled outputs are stored in `.qzn-releases/v{version}/`:
- `Queez-CBT-Suite-Setup-v{version}.exe` (unified NSIS installer for Server, Manager, and Student)
- `release-manifest.json` (build metadata and file hashes)
